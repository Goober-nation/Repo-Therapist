# Аналитика платформы: вкладка «Аналитика» и выгрузка публичных оценок

Статус: 2026-10-07. Относится только к публичным оценкам. Расчёт оценок, категорий и порядок рейтинга
не затрагиваются: всё ниже только читает уже сохранённые данные (см. [grading/00-overview.md](grading/00-overview.md)).

## Что есть

- **Вкладка «Аналитика»** (`/analytics`, доступна без входа): сводка по всем оценённым публичным
  репозиториям.
- **Блок «Как идут оценки»** внизу вкладки: два графика, оценок в сутки и среднее время оценки за две недели.
  Они берутся из метрик сервиса (Prometheus) и считают только публичные оценки; приватные в них не входят.
  Подробнее — [metrics.md](metrics.md).
- **Выгрузка публичных оценок** в CSV и JSON: кнопки на вкладке или прямые ссылки
  `GET /api/export/grades.csv` и `GET /api/export/grades.json`.

## Что показывает вкладка и как это считается, простыми словами

Все числа считает Rating service (только чтение) по таблице публичных оценок `repo_grades_public`,
таблице истории `repo_grade_history` и публичным строкам `repos`. Берутся репозитории с видимостью
`public` и непустой оценкой.

1. **Всего, средний балл, медиана.** Считаются по Score всех оценённых публичных репозиториев;
   среднее и медиана округляются до десятых.
2. **Распределение.** Десять диапазонов по десять баллов (0–9, 10–19, … 90–100), в каждом — число
   репозиториев. Рядом — уровни здоровья: «Отличное» (от 90), «Здоровый» (от 75), «Требует
   внимания» (от 60), «Под риском» (ниже 60); границы те же, что у бейджей и `GET /score`.
3. **Средний балл категории.** Для каждой категории публичной оценки берётся среднее по тем
   репозиториям, у которых по ней есть данные. Категория «нет данных» нулём не считается и в среднее
   не входит; под полосой указано, у скольких репозиториев данные есть.
4. **Средний балл по языкам.** Репозитории группируются по основному языку; показываются языки,
   у которых оценено не меньше 3 репозиториев (среднее по одному-двум репозиториям о языке ничего не
   говорит), до 20 языков, сначала с наибольшим числом репозиториев.
5. **Динамика по неделям.** Для каждой недели берётся последняя оценка каждого репозитория,
   оценённого в эту неделю, и усредняется (последние 12 недель). Это среднее по тому, что платформа
   измерила в эту неделю, а не изменение одного и того же набора репозиториев.
6. **Самые частые рекомендации.** Подсчитывается, у скольких репозиториев в совете есть тот же пункт
   (категория и метрика); показываются 10 самых частых с долей от всех оценённых. Служебное
   уведомление «упрощённая оценка документации» рекомендацией не считается и не показывается.
7. **Больше всего выросли.** Сравнивается последняя оценка с последней оценкой не позднее чем
   `RANKING_DYNAMICS_DAYS` дней назад (по умолчанию 7); показываются 10 репозиториев с наибольшим
   ростом. Репозиторий, оценённый впервые недавно, сравнить не с чем, он в список не попадает.
8. **Кэш.** Результат считается не чаще раза в `ANALYTICS_CACHE_SECONDS` (по умолчанию 300 секунд),
   поэтому вкладка не нагружает базу при частых открытиях.

## Выгрузка

Одна строка на оценённый публичный репозиторий, по порядку «организация, репозиторий».

- **CSV:** `org, repo, url, score, level, language, likes, last_activity_at, graded_at,
  low_confidence, activity, issues, documentation, code_health`. Пустая ячейка значит «нет данных»
  (для категории) или «неизвестно» (для остальных полей); настоящий ноль выгружается как `0`.
  Ячейки, которые начинаются с `=`, `+`, `-`, `@`, получают ведущий апостроф, чтобы электронная
  таблица не выполнила их как формулу.
- **JSON:** `{generated_at, total, grades: [...]}`; у категории есть `score` и `no_data`.
- Выгрузка отдаётся потоком, страницами по 1000 строк. Сбой посреди выгрузки обрывает соединение,
  поэтому оборванный файл нельзя принять за полный (оборванный JSON невалиден).
- Лимит: `EXPORT_RATE_LIMIT` запросов на IP за `EXPORT_RATE_LIMIT_WINDOW` (по умолчанию 5 в минуту,
  свой ключ в Redis), при превышении — `429`.

## Приватность: что сюда не попадает

- Приватные оценки лежат в отдельной таблице `repo_grades_private`, и ни один запрос аналитики её не
  читает; репозитории с видимостью не `public` не попадают ни в агрегаты, ни в выгрузку.
- Выгрузка содержит только то, что уже открыто в публичном рейтинге и `GET /score`; адресов
  электронной почты и токенов в данных нет.

## Ограничения

- История оценок накапливается с 2026-10-05, поэтому «динамика по неделям» и «больше всего выросли»
  в первые недели содержат мало точек.
- Данные кэшируются до 5 минут: только что завершившаяся оценка может появиться на вкладке не сразу.
