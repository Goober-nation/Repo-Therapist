# Рейтинг: история оценок, динамика, сравнение и объяснение места

Статус: 2026-10-05 (фильтры рейтинга добавлены в тот же день). Относится только к публичному рейтингу и публичным оценкам. Приватные оценки в
истории не хранятся. Расчёт оценки и категорий не затрагивается: всё ниже только читает уже
сохранённые данные (см. [grading/00-overview.md](grading/00-overview.md)).

## Что есть

- **История оценок** — каждая публичная оценка репозитория сохраняется отдельной строкой и не
  перезаписывается следующей.
- **Динамика в рейтинге** — рядом с местом и Score показано изменение за последние
  `RANKING_DYNAMICS_DAYS` дней (по умолчанию 7): `▲3` / `▼2` для места и `+4` / `−5` для Score.
- **График истории** на странице репозитория (Score и, по выбору, категории).
- **Сравнение двух репозиториев** — страница `/compare/<орг A>/<репо A>/<орг B>/<репо B>`.
- **«Почему это место»** — карточка на странице репозитория: соседи по рейтингу и разрыв по
  категориям до медианы топ-10.

## Как это считается, простыми словами

### История

1. Когда агрегатор сохраняет публичную оценку, он добавляет строку в `repo_grade_history`: время
   оценки, Score, оценки категорий и флаг низкой достоверности (если он был известен).
2. Ключ строки — репозиторий и время оценки. Повторная доставка того же сообщения Kafka ничего не
   меняет.
3. Сбой записи истории только пишется в лог: оценка при этом сохраняется и считается успешной.
4. При появлении таблицы текущие публичные оценки скопированы в неё как первая точка каждого
   репозитория. Поэтому настоящая история накапливается только с этого момента.
5. Публичные оценки пересчитываются при активности в репозитории и раз в 72 часа для лучших
   репозиториев, так что у большинства репозиториев в первую неделю одна-две точки.

### Изменение Score и места в рейтинге

1. Берётся тот же отфильтрованный список, что показан на странице (тот же язык и то же состояние
   переключателя «Скрыть оценки с низкой достоверностью»).
2. Для каждого репозитория из него находится последняя оценка, сделанная не позже, чем
   `RANKING_DYNAMICS_DAYS` дней назад. Если такой нет (репозиторий оценён позже), изменения нет: в
   интерфейсе стоит метка «новый».
3. **Изменение Score** = текущий Score минус тот Score.
4. **Прошлое место**: репозитории со старой оценкой сортируются по тому старому Score, при равенстве —
   по свежести активности, затем по имени (как в живом рейтинге). Номер в этом списке — прошлое место.
5. **Изменение места** = прошлое место минус текущее: положительное значит «поднялся». Показатель
   считается только при сортировке по Score, потому что при сортировке по лайкам или активности у
   «места» нет устойчивого смысла.
6. Прошлое место считается среди репозиториев, у которых тогда уже была оценка: если выше вас
   появились новые репозитории, место ухудшится, даже если ваш Score не менялся.

### Почему это место

1. Берутся все оценённые публичные репозитории в порядке рейтинга по Score (без фильтров).
2. Находится место репозитория и их общее число.
3. Показываются сосед выше и сосед ниже и разница их Score с вашим. Нулевая разница — это ничья,
   решённая более свежей активностью.
4. Для каждой категории с данными считается медиана по десяти лучшим репозиториям (только по тем,
   у кого категория есть; нужно не меньше трёх значений). Разница = ваш балл минус медиана.
5. Категория с самой отрицательной разницей названа «сильнее всего отстаёт». Если отрицательных нет,
   так и сказано.
6. Категории «нет данных» не показываются: отсутствие данных не считается плохим результатом.

### Сравнение

Страница читает для каждого репозитория публичную оценку (`GET /score`) и историю
(`GET /history`). Показаны Score, четыре публичные категории, разница A − B и общий график двух
линий Score. Выбрать репозитории можно галочками «Сравнить» в рейтинге (ровно два) или ввести
`организация/репозиторий` либо ссылку SourceCraft на самой странице; адрес страницы можно
отправить другому человеку. Непубличный или неизвестный репозиторий показывается как «не найден
среди публичных».

### Фильтры рейтинга

Кроме языка и переключателя низкой достоверности, рейтинг фильтруется по четырём признакам. Все они
смотрят на сам репозиторий, а не на результаты проверок: чужие результаты CI и AppSec для публичных
репозиториев недоступны (их видит только владелец).

1. При каждой публичной оценке Grade service собирает факты: число файлов и строк кода (из той же
   выгрузки, что нужна для флага низкой достоверности), наличие файла настройки CI (из
   `ci-runs.json`) и наличие `SECURITY.md` (также `security.md`, `SECURITY.rst`,
   `.github/SECURITY.md`, `docs/SECURITY.md`). Факт, который установить не удалось, остаётся
   неизвестным (`null`), а не «нет».
2. Aggregator сохраняет факты в `repo_facts_public` (одна строка на репозиторий, перезаписывается при
   новой оценке) и описание репозитория — в `repos.description`.
3. **Размер** — по числу строк кода: малый — меньше `RANKING_SIZE_SMALL_LOC` (2000), большой — не
   меньше `RANKING_SIZE_LARGE_LOC` (20000), средний — между ними (граница включается в старший класс).
4. **CI** — «есть конфиг» / «нет конфига»: говорит, что пайплайн настроен, а не что он проходит.
5. **Политика безопасности** — «есть SECURITY.md» / «нет SECURITY.md». Это не результат сканирования AppSec.
6. **Тематика** — поиск слов в названии и описании репозитория без учёта регистра. У SourceCraft нет
   тем (topics), поэтому тематика определяется только по тексту описания; пустое описание ничего не
   находит. Служебные символы `%` и `_` ищутся как обычный текст.
7. Фильтры соединяются через «и». Репозиторий, для которого нужный факт неизвестен или у которого ещё
   нет строки фактов, ни под «есть», ни под «нет» не попадает: неизвестное не считается отсутствием.
8. Общее число (`total_count`), список, изменение места и счётчик страниц считаются по одной и той же
   выборке, поэтому изменение места показывает сравнение внутри отфильтрованного списка.
9. Оценка, сохранённая до появления фактов, пересчитывается при первом открытии репозитория (как и
   оценка без аналитики), после чего репозиторий появляется в фильтрах по фактам.

## API

Все маршруты публичные, только для чтения, без ключа, с `Access-Control-Allow-Origin: *`; лимит
запросов тот же, что у `/score` (`PUBLIC_API_RATE_LIMIT`). Подробности полей — в
[api_docs.md](api_docs.md).

| Запрос | Ответ |
|---|---|
| `GET /ranking` | в каждой записи `score_change` и `place_change` (`null` — «новый» или сортировка не по Score), в ответе `dynamics_days`; фильтры `size=small\|medium\|large`, `ci=true\|false`, `security=true\|false`, `topic=<текст до 64 символов>`; неверное значение — `400` |
| `GET /history/{org}/{repo}` | `{status, points: [{graded_at, score, categories, low_confidence}]}`, от старых к новым, не больше 200 последних точек; `NO_DATA`, если истории нет |
| `GET /position/{org}/{repo}` | `{status, place, total, score, above, below, categories: [{id, score, top10_median, gap}], weakest_category}`; `NO_DATA`, если репозиторий ещё не оценён |

## Настройки

| Переменная | Где | По умолчанию | Смысл |
|---|---|---|---|
| `RANKING_DYNAMICS_DAYS` | rating-service | 7 | окно изменения Score и места |
| `RANKING_SIZE_SMALL_LOC` | rating-service | 2000 | граница малого размера (строк кода) |
| `RANKING_SIZE_LARGE_LOC` | rating-service | 20000 | граница большого размера (строк кода); должна быть больше малой, иначе берутся значения по умолчанию |

## Известные ограничения

- История начинается с момента появления таблицы; до этого у репозитория одна точка. Пока прошло
  меньше `RANKING_DYNAMICS_DAYS` дней, изменения в рейтинге не видны («новый»).
- Фильтры по CI и безопасности показывают наличие файлов настройки, а не результаты проверок;
  «тематика» — это поиск по тексту описания, а не классификатор: у SourceCraft нет тем и размера
  репозитория (размер берётся из строк кода нашего клона). Репозитории с неизвестным фактом в
  выборках по этому факту не участвуют.
- Место считается по всему списку в памяти сервиса; для десятков тысяч репозиториев потребуется
  отдельный запрос с оконной функцией.
- Сравнение — ровно два репозитория; только публичные оценки.
