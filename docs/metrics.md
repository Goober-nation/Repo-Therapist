# Метрики и графики работы сервиса (Prometheus)

Статус: 2026-10-08. Метрики только считают то, что сервисы уже делают. Расчёт оценок и порядок рейтинга не
затрагиваются.

## Что есть, простыми словами

- Три сервиса на Go (Gateway, Aggregator, Rating) и сервис LLM на Python отдают свои числа на отдельном порту: сколько было запросов,
  сколько оценок запущено и завершено, сколько они длились, сколько отказов по лимитам.
- **Prometheus** раз в 15 секунд забирает эти числа и хранит их 15 дней (`PROMETHEUS_RETENTION`).
- **Графики рисует сам сайт**, Grafana нет (решение 2026-10-08). Gateway спрашивает у Prometheus готовые
  числа и отдаёт их странице:
  - **в администраторской части вкладки «Доступ админа»** — блок «Работа сервиса» с десятью графиками и выбором
    периода (час, 6 часов, сутки, неделя) и блок «Расход LLM» с пятью графиками токенов и вызовов модели;
  - **на вкладке «Аналитика»** — блок «Как идут оценки» с двумя графиками для всех: «Оценок в сутки» и
    «Среднее время оценки».
- Во вкладке и на графиках только числа и время. Репозиториев, пользователей, IP и токенов в метриках нет.

## Как это устроено

```
Gateway :9101 ┐
Aggregator :9102 │
Rating :9103 ├──► Prometheus ◄── Gateway (ограниченный набор запросов) ──► страница
llm-service :9104 │
llm-summary-service :9105 ┘
```

- Порты метрик (`METRICS_ADDRESS`, своя у каждого сервиса, в контейнере выставляет `docker/go-entrypoint.sh`)
  **не публикуются** наружу; Prometheus ходит к ним по внутренней сети. Интерфейс самого Prometheus
  привязан только к localhost: `http://localhost:8056`.
- **Браузер не присылает запросов на языке PromQL.** Он называет один из фиксированных графиков и один из
  фиксированных периодов; Gateway сам знает запрос для каждого. Так страница не может прочитать чужие метрики или
  запустить тяжёлый запрос.
- Ответ на график кэшируется на `SERIES_CACHE_SECONDS` (60): сколько бы людей ни смотрело, Prometheus
  получает один запрос.
- Если Prometheus не задан (`PROMETHEUS_URL` пуст) или не отвечает, графики показывают понятное сообщение, а
  остальная вкладка работает как обычно.

## Что считается

Метки только из фиксированных слов: шаблон маршрута (`GET /score/{org}/{repo}`, а не настоящий путь),
видимость (`public`/`private`), причина, код ответа. Неизвестный путь попадает в метку `unmatched`.

| Метрика | Сервис | Что означает |
|---|---|---|
| `gateway_http_requests_total{route,status}` | Gateway | запросы по шаблону маршрута и коду ответа |
| `gateway_http_request_duration_seconds{route}` | Gateway | время ответа |
| `gateway_grpc_client_calls_total{target,method,code}` и `..._duration_seconds` | Gateway | вызовы Aggregator и Rating: сколько и с каким результатом |
| `gateway_admin_denied_total{reason}` | Gateway | отказы в админских маршрутах (все, не только записанные в журнал) |
| `gateway_admin_unlock_total{result}` | Gateway | попытки входа по паролю: `ok`, `wrong_password`, `locked`, … |
| `aggregator_gradings_requested_total{visibility,trigger}` | Aggregator | запущено оценок; `trigger` — `user`, `schedule` или `batch` |
| `aggregator_gradings_completed_total{visibility,outcome}` | Aggregator | получено результатов: `ok` или `error` |
| `aggregator_grading_duration_seconds{visibility,outcome}` | Aggregator | время от запроса до результата |
| `aggregator_grade_limiter_rejections_total` | Aggregator | оценок отклонено общим лимитом |
| `aggregator_llm_requests_total{outcome}` | Aggregator | запросы рекомендаций: `requested`, `publish_failed`, `received_ok`, `received_error` |
| `aggregator_grading_batch_items_total{status}`, `..._events_total{event}` | Aggregator | репозитории и события пакетной оценки (до 2026-10-09 — `aggregator_regrade_batch_*`) |
| `aggregator_scheduled_regrade_*` | Aggregator | ход плановой переоценки (идёт ли, всего, обработано) |
| `aggregator_grpc_requests_total{method,code}` и `..._duration_seconds` | Aggregator | запросы к самому Aggregator |
| `rating_grpc_requests_total{method,code}` и `..._duration_seconds` | Rating | запросы к Rating |
| `rating_analytics_cache_total{result}` | Rating | аналитика из кэша (`hit`) или пересчитана (`miss`) |
| `llm_model_calls_total{model,purpose,outcome}` | LLM | вызовы модели: `purpose` — `summary` или `documentation`, `outcome` — `ok`, `rate_limited`, `content_filtered`, `timeout`, `error`; повтор после неверного формата — отдельный вызов |
| `llm_model_tokens_total{model,purpose,kind}` | LLM | токены из поля `usage` ответа модели: `input`, `output`, `cached_input` (часть входных, которую провайдер отдал из кэша) |
| `llm_model_call_duration_seconds{model,purpose}` | LLM | время вызова |
| `go_*`, `process_*` | Go-сервисы | память, горутины, процессор |

Две особенности, которые нужно знать:

- **Известные ряды стартуют с нуля.** Счётчик, который впервые появляется сразу со значением 3, для Prometheus
  не имеет предыдущего значения, и `increase()` показал бы 0. Поэтому сервисы создают известные сочетания меток при
  запуске.
- **Подсчёты на графиках округлены.** `increase()` в Prometheus растягивает значение по окну, поэтому «4 оценки»
  могли бы показаться как 4,09; запросы со счётом обёрнуты в `round()`.
- Время оценки замеряется в памяти Aggregator между запросом и результатом. Если Aggregator перезапустили
  посередине, результат считается, но время не записывается.

## Графики

| Имя | Где | Что показывает | Только публичные? |
|---|---|---|---|
| `gradings_per_day`, `grading_avg_seconds` | вкладка «Аналитика» | оценок за 24 часа до каждой точки (две недели, шаг сутки) и среднее время | да: запросы фильтруют `visibility="public"`, тест это проверяет |
| `http_rate`, `http_latency_p95`, `grpc_errors` | админская часть | нагрузка, время ответа, сбои между сервисами | нет |
| `gradings_by_trigger`, `grading_outcomes`, `grading_p95_seconds`, `limiter_rejections` | админская часть | запуски, результаты и время оценок, отказы по лимиту | нет |
| `llm_requests`, `batch_items`, `admin_denied` | админская часть | запросы к LLM, пакеты переоценки, отказы администратору | нет |
| `llm_tokens_per_day`, `llm_tokens`, `llm_tokens_by_purpose`, `llm_calls`, `llm_call_p95_seconds` | админская часть, блок «Расход LLM» | токены за сутки (две недели) и за час, на что они уходят (рекомендации или документация), вызовы по итогу, время вызова | нет, только администратору |

Последняя точка графика — «сейчас». Для суточных графиков точка — число за 24 часа до неё, поэтому оценки
сегодняшнего дня видны сразу, а не после следующей полуночи. Вкладка «Аналитика» остаётся публичной: приватные
оценки в эти графики не попадают, потому что публичные запросы фильтруют по `visibility="public"`.

## Маршруты

| Маршрут | Доступ | Ответ |
|---|---|---|
| `GET /stats/series/{name}` | любой | график вкладки «Аналитика»: `{name, unit, step_seconds, generated_at, series: [{label, points: [[время, значение]]}]}`; `Cache-Control: public, max-age=60`; имя админского графика — `404`; лимит запросов как у остального публичного API; `503` с `code` `metrics_off` или `metrics_unavailable` |
| `GET /admin/metrics/{name}?range=1h\|6h\|24h\|7d` | админ | то же для графиков администратора; по умолчанию `24h`; неверный период — `400`, неизвестный график — `404`; без кэша |

Точки без значения (деление на ноль, пропуски) не рисуются: пустое место честнее выдуманного нуля.

## Настройки

| Переменная | Где | По умолчанию | Назначение |
|---|---|---|---|
| `METRICS_ADDRESS` | Gateway, Aggregator, Rating | пусто (выкл.) | на каком адресе отдавать `/metrics`; в контейнере `:9101`, `:9102`, `:9103` |
| `LLM_METRICS_PORT` | сервис LLM | пусто (выкл.) | порт `/metrics`; в compose `9104` у `llm-service` и `9105` у `llm-summary-service` |
| `PROMETHEUS_URL` | Gateway | `http://prometheus:9090` в compose | откуда брать числа для графиков; пусто — графики выключены |
| `SERIES_CACHE_SECONDS` | Gateway | 60 | на сколько кэшировать ответ графика |
| `PROMETHEUS_RETENTION` | Prometheus | 15d | сколько хранить метрики |

## Как проверить на своей машине

```bash
docker compose up -d --build
```

Затем `http://localhost:8056/targets`: три цели (`gateway`, `aggregator`, `rating`) должны быть `UP`. Числа сервиса
напрямую: в контейнере `go-services` порты 9101, 9102 и 9103 (`curl localhost:9102/metrics` изнутри контейнера).
Графики: вкладка «Аналитика» (внизу) и вкладка «Доступ админа» для администратора.

## Расход LLM: токены, не деньги

- Токены берутся из поля `usage` ответа Yandex AI Studio, то есть считаются так, как их считает провайдер. Поле
  проверено настоящим вызовом: в нём `input_tokens`, `output_tokens` и `cached_tokens` внутри `input_tokens_details`.
- **Денег нет.** Цены нигде не заданы и не угадываются (решение 2026-10-09: «только токены»). Если цена понадобится, её
  умножают на эти же счётчики, ничего в сборе менять не придётся.
- **Модель вызывается не всегда.** Рекомендации (`llm-summary-service`) идут через модель каждый раз; оценка
  документации по умолчанию считается без модели (`LLM_DOCS_MODE=algorithmic`) и появится на графиках только при
  `LLM_DOCS_MODE=auto`.
- Один запрос может стоить два вызова: при неверном формате ответа сервис просит модель исправиться. Это видно
  на графике вызовов.
- Токены учитываются и тогда, когда ответ потом отклонён (отфильтрован, неверный формат): они оплачены.
- В метках нет ни репозиториев, ни пользователей, ни текста запроса, ни папки облака или ключа: метка `model` — это
  имя из настройки (`aliceai-llm`), а не адрес из ответа провайдера, в котором есть идентификатор папки.
- Графики токенов построены из `increase()`: на краях периода они могут отличаться от точной суммы на единицы токенов
  (например, 49 вместо 48). Точные суммы — в самих счётчиках на `/metrics`.

## Как добавить метрику или график

1. Метрика: поле и метод в пакете `internal/metrics` сервиса (у сервиса LLM — `src/llm_service/metrics.py`); известные
   сочетания меток создайте при старте. Метки только из фиксированных слов.
2. График: запись в `Catalog` пакета `backend/gateway-service/internal/series` (имя, единица, запрос; для публичного —
   фильтр `visibility="public"`, иначе тест не пройдёт) и такое же имя с русским названием в
   `frontend/src/seriesView.ts`.

## Ограничения

- Пока Prometheus не накопил истории, графики состоят из нескольких точек; суточные станут содержательными через
  несколько дней работы.
- Метрики хранятся 15 дней и теряются при удалении тома `promdata`.
- Расход LLM показан в токенах, без цены (см. выше). Токены считаются с момента, когда сервис LLM пересобран с метриками.
- Лаг очереди Kafka не измеряется (нужен отдельный экспортёр).
